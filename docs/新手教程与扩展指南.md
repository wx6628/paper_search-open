# 新手教程与扩展指南

> 本文分两部分：
> - **第一部分：从零开始**。面向第一次接触命令行和 AI 编程助手的“小白”用户，从安装到熟练使用，一步一步来。
> - **第二部分：在基础版上扩展**。按自己的研究领域定制，新增命令、数据源，接入其他 AI 工具，修改界面。
>
> 功能细节（每个按钮、每个参数）请查 `docs/操作指南.md`，本文只讲“怎么用起来”和“怎么改”。

# 第一部分：从零开始

## 0. 先了解：它能帮你做什么

想象你要写一篇论文的相关工作，或者刚进入一个新方向：

1. 你对 AI 助手说：“帮我检索**小样本目标检测中的元学习方法**”。
2. AI 在你电脑上的 dblp 库里（数百万篇论文）按标题检索，再去 OpenAlex、arXiv 等网站找 dblp 还没收录的最新论文。
3. AI 逐篇看标题和摘要，挑出真正相关的 15–40 篇，每篇写一句“为什么相关”。
4. 这些论文自动进入你的**个人文献库**并建好分组，同时生成一份检索报告（Markdown）和一份 BibTeX。
5. 你在浏览器里打开文献库：看摘要、下载开放获取 PDF、标星、写笔记；把想深读的论文点“加入 AI 精读队列”。
6. 回到 AI 助手说“处理队列”，AI 读完全文，按固定模板写出结构化精读笔记，挂到这篇论文上。
7. 写论文时一键导出 BibTeX；投稿前让 AI 核验参考文献，揪出写错甚至不存在的条目。

### 你需要准备

| 项目 | 要求 |
|---|---|
| 电脑 | Windows 10/11、macOS 或 Linux |
| 磁盘 | **至少 12 GB 空闲**（dblp 数据包约 1.1 GB，构建后的本地库约 8 GB） |
| Python | 3.10 或更高版本（推荐 3.12） |
| 网络 | 下载数据包和在线补全需要联网；本地检索不需要 |
| AI 工具（可选但推荐） | Claude Code、Codex 等任一种。不用 AI 也能用图形界面的大部分功能（见第 10 节） |

## 1. 安装 Python

**Windows**

1. 打开 https://www.python.org/downloads/ ，下载最新的 Python 3.12 或 3.13 安装包。
2. 运行安装包，**务必勾选底部的 “Add python.exe to PATH”**，然后点 “Install Now”。
3. 验证：按 `Win + R`，输入 `cmd` 回车，在黑色窗口里输入：
   ```
   python --version
   ```
   看到 `Python 3.12.x` 之类的输出就成功了。

**macOS**：从 python.org 下载安装包，或用 Homebrew：`brew install python`。验证命令是 `python3 --version`。

> 下文命令统一写 `python`。macOS / Linux 如果提示找不到命令，就把 `python` 换成 `python3`。

---

## 2. 获取项目

二选一：

- **不会用 git**：在项目主页点 “Code → Download ZIP”，解压到一个好找的位置，例如 `D:\paper_search-open`。
- **会用 git**：`git clone <项目地址>`。

建议放在**空间充足的磁盘**（本地 dblp 库约 8 GB），路径里最好不要有空格。

### 怎么“在项目目录打开终端”

后面很多步骤都要在项目目录里运行命令：

- **Windows**：打开项目文件夹，点资源管理器上方的地址栏，输入 `cmd` 回车，会弹出一个已经在这个目录里的命令行窗口。
- **macOS**：在“访达”里右键项目文件夹 → “新建位于文件夹位置的终端窗口”（需在系统设置里启用），或在终端输入 `cd ` 后把文件夹拖进去再回车。

---

## 3. 安装依赖

在项目目录的终端里运行：

```
python -m pip install -r requirements.txt
```

国内网络较慢时，可以用清华镜像：

```
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

会安装三个包：`lxml`（解析 dblp）、`PyYAML`（读配置）、`PyMuPDF`（读 PDF）。

---

## 4. 下载 dblp 数据包并构建本地库

这是唯一一个比较耗时的步骤，**只需做一次**，之后每月更新一次即可。

### 4.1 下载

推荐 **月度稳定版**（下载快）：

1. 打开 https://drops.dagstuhl.de/entities/collection/10.4230/dblp.xml
2. 点最新的一期，下载 `dblp-YYYY-MM-DD.xml.gz`（约 1.1 GB），有 `.md5` 校验文件的话一起下载。
3. 把下载的文件放进项目的 `data\dblp\` 文件夹。这个文件夹里已经有一个 `dblp.dtd`，**不要删它**。

> 也可以下载每日版 https://dblp.org/xml/dblp.xml.gz ，更新但下载更慢。这是唯一允许访问 dblp.org 的情况，而且是你自己用浏览器下载。工作站的程序从不在线访问 dblp。

### 4.2 构建

在项目目录的终端里运行（把文件名换成你下载的那个）：

```
python -I ps/dblp_build.py --dump data/dblp/dblp-2026-11-01.xml.gz --db data/dblp.sqlite
```

- 大约需要 **6–15 分钟**，期间会显示进度（已解析多少条记录）。
- 结束后检查一下：
  ```
  python -I ps/dblp_query.py stats
  python -I ps/dblp_query.py search "object detection" --limit 5
  ```
  能看到论文列表就说明本地库可以用了。
- 构建成功后，原始的 `.xml.gz` 可以删掉以节省空间，也可以留着。

> 也可以在 AI 助手里说 `/dblp-update`（或“更新 dblp”），让 AI 替你运行。

## 5. 配置 API key（可选，强烈推荐）

不配置也能用：本地检索完全离线。配置后，**补摘要**和**找最新论文**的效果会好很多，而且这些服务都是免费的。

1. 在项目目录里找到 `.env.example`，**复制一份，改名为 `.env`**。
   - Windows 注意：文件名就是 `.env`，没有 `.txt` 后缀。可以在资源管理器“查看”里勾选“文件扩展名”来确认。
2. 用记事本打开 `.env`，按里面的说明填写：

| 变量 | 怎么获得 | 作用 |
|---|---|---|
| `CROSSREF_MAILTO` | 填你的邮箱即可 | Crossref 查新论文、核验引用（更不容易被限流） |
| `UNPAYWALL_EMAIL` | 填你的邮箱即可 | 找开放获取 PDF |
| `OPENALEX_API_KEY` | 在 https://openalex.org 注册，在账户设置里获取 | 补摘要、查最新期刊/会议论文。**最重要的一个**：不填的话 OpenAlex 会直接拒绝请求（429） |
| `SPRINGER_META_API_KEY` | 在 https://dev.springernature.com 注册申请 | 补 Springer 系列会议（如 ECCV）的摘要 |

3. 保存。**不要把 key 发到 AI 对话里**，AI 也不会向你要 key。
4. 想确认能不能用：对 AI 说“测试一下 key 能不能用”，或者运行 `python -I ps/netlib.py` 查看用量。

> 用量限制写在 `config/api_limits.yaml` 里，默认已设成官方额度的 50%–80%，一般不需要改。

## 6. 配置你的“优先出处”

`config/venues.yaml` 决定哪些会议、期刊算“优先”，以及它们的层级（tier 1 最优先）。项目自带的只是**示例**：CVPR、NeurIPS、ICLR、TPAMI（tier 1），ECCV、TIP（tier 2）。

**请换成你自己领域认可的出处。** 最简单的做法是对 AI 助手说：

```
/venues tier 1：CVPR、ICCV、ECCV、TPAMI、TIP；tier 2：WACV、BMVC、Pattern Recognition；删掉 NeurIPS 和 ICLR
```

AI 会自动完成这些事：核对每个出处在 dblp 里的编号；把 workshop 排除在外（dblp 里 workshop 常和正会共用一个编号）；查好 OpenAlex 编号和 ISSN；选好查新论文用的数据源；写进配置；重新计算库里已有论文的层级。

同一文件里的 `year_priority` 决定年份档，默认是 **2024 年及以后 > 2021–2023 > 2021 年以前**。年份档只影响排序，不会过滤掉老论文。改完对 AI 说“重新计算层级”。

## 7. 准备 AI 助手

工作站的规则写在项目根目录的 `AGENTS.md`，每个命令的步骤写在 `docs/workflows/`。下面几种 AI 工具都能读懂：

| AI 工具 | 安装（以官方文档为准） | 在本项目里怎么用 |
|---|---|---|
| **Claude Code** | 见 Anthropic 官方文档（Claude Code） | 在项目目录启动，用 `/find`、`/queue` 等斜杠命令；输入 `/` 可以看到全部命令 |
| **Codex** | 见 OpenAI 的 Codex 项目主页 | 在项目目录启动，它会自动读 `AGENTS.md`。没有斜杠命令，用自然语言说：“执行 find：小样本目标检测” |
| 其他（Gemini CLI、Cursor……） | 各自官网 | 先让它读 `AGENTS.md`，然后同样用自然语言说命令名 |

**关键：一定要在项目目录里启动 AI 工具**，否则它看不到工作站的规则和命令。

如果 AI 工具运行在沙盒里，可能默认禁止联网。检索新论文、补摘要时如果报“连接失败”，按工具提示允许联网即可。

## 8. 第一次完整使用（跟着做一遍）

### 第 1 步：检索

在 AI 助手里输入（中英文都可以）：

```
/find 小样本目标检测中的元学习方法
```

Codex 里说：`执行 find：小样本目标检测中的元学习方法`。

等几分钟，AI 会告诉你：找到多少候选、保留了多少篇、按层级和年份档怎么分布、最值得先读的 3–5 篇，以及报告、BibTeX 的路径和分组名。

> 想指定分组：`/find 小样本目标检测中的元学习方法 目标检测/小样本`（格式是 `大组/小组`，不存在会自动创建）。

### 第 2 步：打开图形界面

- Windows：双击项目目录里的 **`打开论文库.bat`**
- macOS / Linux：在终端运行 `./start.sh`（第一次可能要先 `chmod +x start.sh`）
- 或者对 AI 说 `/library`

浏览器会打开 http://127.0.0.1:8765 。**那个黑色的服务器窗口不要关**，关了界面就断开。

### 第 3 步：浏览与整理

- 左侧点刚才的分组，中间是论文列表，点标题右侧会打开详情。
- 每篇论文的徽章：**T1/T2/T3** 是出处层级，**Y1/Y2/Y3** 是年份档，**L0–L3** 是补全程度（L0 只有标题，L1 有摘要，L2 有 PDF，L3 有笔记/精读）。
- 勾选多篇后，顶部可以批量：改状态（待读/在读/已读）、加星、加入分组、补全摘要、下载开放获取 PDF。

### 第 4 步：拿到 PDF

- 开放获取的论文：详情面板点“下载开放获取版本”。
- 付费论文：用校园网或机构账号自己下载，然后**把 PDF 拖进详情面板的虚线框**；或者在“本地 PDF 路径”里粘贴路径，点“关联”。
- 关联 PDF 后，如果论文还没有摘要，会自动从 PDF 首页提取。

### 第 5 步：AI 精读

1. 在详情面板点 **“加入 AI 精读队列”**（可以多选后批量加入）。
2. 回到 AI 助手输入 `/queue`（Codex 里说“处理队列”）。
3. AI 读完全文后生成 Markdown 笔记，存在 `library/ai_notes/<大组>/<小组>/`，并自动挂到论文上。刷新浏览器就能在详情面板里看到。

笔记的结构固定为：锐评 → 一句话总结 → **创新思路主线**（背景 → 问题 → Idea → 机制 → 贡献）→ 方法 → 实验 → 关联笔记。想改格式，见第 13 节。

### 第 6 步：写论文

```
/bib 目标检测/小样本          # 导出这个小组的 BibTeX
/bib starred                 # 导出所有星标论文
/verify D:\我的论文\refs.bib   # 核验参考文献（也可以直接把参考文献粘贴给 AI）
```

`/verify` 会逐条标出 ✅ 已核实、⚠️ 有出入（并给出正确值）、❌ 查无此文（可能是写错了，或是 AI 编造的引用），最后输出一份修正后的 BibTeX。

## 9. 日常使用路线图

| 场景 | 做法 |
|---|---|
| 进入一个新方向 | `/find <问题>`，读报告，挑 5 篇加入精读队列，`/queue` |
| 每周追新论文 | `/fresh <关键词>`，只看 dblp 还没收录的优先出处新论文，挑中的入库 |
| 检索结果不够全 | 直接对 AI 说“再从 xxx 角度补充检索”，结果会进同一分组 |
| 摘要缺很多 | `/enrich <分组>`；Elsevier 期刊在线没有摘要，关联 PDF 后会自动提取 |
| 整理思路 | 在详情面板给论文加“关联”（改进自 / 对比了 / 基于……），左侧“🕸 关系图”可以看脉络 |
| 写相关工作 | 分组 → 导出 BibTeX；精读笔记里的“创新思路主线”可以直接当写作素材 |
| 投稿前 | `/verify` 核验全部参考文献 |
| 每月一次 | 下载新的 dblp 数据包，`/dblp-update` |

## 10. 不用 AI 也能做的事

图形界面本身就能独立使用：

- **🔎 dblp 目录检索**（左侧）：在本地数百万篇论文里按标题检索，可以限定层级和年份，勾选后“加入文献库”。完全离线，不耗任何额度。
- 分组、星标、阅读状态、笔记、关系图、PDF 关联与阅读。
- 批量“补全摘要”“下载开放获取 PDF”“从 PDF 提取摘要”“导出 BibTeX”。

需要 AI 的只有：智能检索与筛选（find）、精读（queue）、核验参考文献（verify）、配置出处（venues）。不过这些也都有命令行脚本可以手动运行，见 `docs/操作指南.md` 第 9 节。

## 11. 新手常见问题

| 问题 | 解决 |
|---|---|
| `python` 不是内部或外部命令 | 安装 Python 时没勾选 “Add to PATH”。重新运行安装包，选 “Modify”，勾上它；或者把命令里的 `python` 换成 `py` |
| `No module named 'yaml'` / `'lxml'` / `'pymupdf'` | 没装依赖：回到第 3 步 |
| `dblp.sqlite not found` | 还没构建本地 dblp：回到第 4 步 |
| 构建 dblp 时报 `dblp.dtd not found` | `dblp.dtd` 必须和 `.xml.gz` 在同一个文件夹（`data/dblp/`） |
| 双击 bat 后窗口一闪就没了 | 在项目目录打开终端，手动运行 `python -I ps/server.py`，看报错信息 |
| 浏览器打不开 127.0.0.1:8765 | 服务器窗口被关了，重新双击 bat |
| AI 助手不认识 `/find` | 没在项目目录启动，或用的是 Codex 等工具（改用自然语言：“执行 find：……”） |
| 检索提示某个数据源被停用 | 触发了限流或人机验证，工作站会自动停用该源来保护你的账号。过一会儿或第二天再试 |
| 担心误删 | 删分组不会删论文，删论文不会删 PDF 和笔记。重要操作前可以先备份 `library/` 文件夹 |

## 12. 数据、隐私与备份

- **所有个人数据都在本机**：`library/`（文献库、PDF、笔记）、`data/`（本地 dblp、用量记录）、`reports/`、`exports/`、`.env`。图形界面只监听 127.0.0.1，局域网里的其他电脑访问不到。
- **会联网的只有**：向 OpenAlex、Crossref、OpenReview、arXiv、Springer、Unpaywall 发出的检索/补全请求，以及开放获取 PDF 的下载。
- **备份**：关闭图形界面后，复制整个 `library/` 文件夹即可。外部关联的 PDF（没有复制进库的）需要自己保管原文件。
- **换电脑**：复制整个项目文件夹（包括 `library/`、`.env`）。本地 dblp 太大的话，可以不复制 `data/`，到新电脑上重新构建。
- **不建议**在网盘同步目录里一边同步一边使用（数据库文件同步到一半可能损坏）。

# 第二部分：在基础版上扩展

> 下面每一项都可以直接把需求告诉 AI 助手，让它照着本节去改。例如：
> “参考 `docs/新手教程与扩展指南.md` 的 E4 节，帮我接入 xxx 数据源。”
> 改动前建议先备份，或者用 git 提交一次，改坏了可以退回。

## E1. 定制检索策略

| 想改什么 | 改哪里 |
|---|---|
| 优先出处、层级 | `config/venues.yaml`（推荐用 `/venues` 让 AI 改） |
| 年份档的划分 | `config/venues.yaml` 的 `year_priority`，例如改成 `{from: 2025}`、`{from: 2022, to: 2024}`、`{to: 2021}` |
| 各年份档的名额比例（默认 50% / 30% / 20%） | `ps/search.py` 顶部的 `BAND_QUOTA` |
| 每层检索多少候选、补多少摘要 | `ps/search.py gather` 的参数 `--per-tier`（默认 40）、`--abstracts`（默认 80），也可以在 `docs/workflows/find.md` 里写明默认参数 |
| 非优先出处要不要出现 | `gather --others 0` 表示不要 |
| API 限速 / 每日上限 | `config/api_limits.yaml` 里的 `limit_*` 值（建议不超过官方额度的 80%） |

## E2. 定制 AI 的行为

| 想改什么 | 改哪里 |
|---|---|
| 精读笔记的格式 | `docs/精读笔记模板.md`。直接增删章节就行，例如加一节“与我课题的关系”，AI 下次精读就按新格式写 |
| AI 回复的语言 | `AGENTS.md` 里的 “Write replies to the user in Chinese.” |
| 检索时的筛选标准（保留多少篇、怎么写理由） | `docs/workflows/find.md` 第 4 步 |
| 全局规则（比如“不要下载 PDF”） | 在 `AGENTS.md` 的 Hard rules 里加一条 |

**原则**：规则写在 `AGENTS.md`，流程写在 `docs/workflows/`。不要只改 `CLAUDE.md` 或某个 AI 专用的文件，否则换一个 AI 工具就失效了。

## E3. 新增一个命令（工作流）

举例：想要一个“周报”命令，每周对几个关键词跑一次 fresh，汇总成一份报告。

**第 1 步**：新建 `docs/workflows/weekly.md`，写清楚 AI 要做什么（用英文或中文都可以，写清楚就行）：

```markdown
# Workflow: weekly — 每周新论文周报

Input: 若干关键词（用逗号分隔），可选 --since 日期（默认 7 天前）。

1. 对每个关键词运行 `python -I ps/fresh.py "<keyword>" --since <date>`。
2. 合并结果、去重，按出处分组；每篇写一句中文要点（基于摘要），并标注状态（已发表 / 已录用 / arXiv 声明录用）。
3. 把周报写到 `reports/weekly_<日期>.md`。
4. 问用户要不要把其中一些论文入库（`ps/library.py import`）。
5. 最后运行 `python -I ps/scratch.py clean`。
```

**第 2 步**：在 `AGENTS.md` 的 Workflows 表格里加一行：

```
| weekly | `/weekly <关键词>`, "出本周周报" | `docs/workflows/weekly.md` | 每周新论文周报 |
```

**第 3 步（只针对 Claude Code）**：新建 `.claude/commands/weekly.md`，让 `/weekly` 斜杠命令生效：

```markdown
---
description: 每周新论文周报
argument-hint: <关键词，逗号分隔> [--since YYYY-MM-DD]
---

Open `docs/workflows/weekly.md` and follow it exactly, together with the rules in AGENTS.md.

User input: **$ARGUMENTS**
```

完成后重启 AI 工具。Claude Code 用 `/weekly 目标检测, 语义分割`，Codex 说“执行 weekly：目标检测, 语义分割”。

> 写工作流的诀窍：每一步给出**确切的命令**，说明**输出写到哪里**，最后一步**清理中间文件**。AI 按步骤执行最稳定。

## E4. 新增一个在线数据源（找新论文）

“dblp 缺口”层在 `ps/fresh.py`，每个数据源是一个 `from_xxx()` 函数，返回统一格式的记录。接入新源分四步：

**① 在 `config/api_limits.yaml` 里给它定限额**（所有网络请求都要经过 `netlib`，它按这里的数值限速、记账）：

```yaml
mysource:
  official: {per_second: 5}
  limit_per_second: 2
  limit_daily: 1000
```

**② 在 `ps/fresh.py` 里写一个函数**，模仿 `from_openalex`：

```python
def from_mysource(q: str, venues: list[dict], since: dt.date, limit: int) -> list[dict]:
    use = [v for v in venues if "mysource" in (v.get("fresh") or [])]
    if not use:
        return []
    d = netlib.call("mysource", "https://api.example.org/search",
                    {"q": q, "from": str(since), "rows": limit, "key": netlib.env("MYSOURCE_API_KEY")})
    out = []
    for it in d.get("items", []):
        v = ...  # 把结果对应到 use 里的某个出处，对不上就跳过
        out.append(new_rec(title=clean(it["title"]), year=it.get("year"), doi=it.get("doi"),
                           venue=v["name"], venue_short=v["short"], tier=v["tier"],
                           abstract=it.get("abstract"), url=it.get("url"), sources=["mysource"]))
    return out
```

**③ 在 `main()` 的 `steps` 列表里登记**，并把名字加进 `--sources` 的默认值：

```python
steps = [..., ("mysource", lambda: from_mysource(a.query, venues, since, a.limit))]
```

**④ 在 `config/venues.yaml` 里，给需要的出处的 `fresh:` 列表加上 `mysource`**。需要 key 的话，在 `.env.example` 里加一行变量名，在 `.env` 里填值。

测试：`python -I ps/fresh.py "object detection" --sources mysource`。

> 注意：只接入**提供公开 API** 的数据源，并遵守对方的使用条款；不要抓取会弹人机验证的网站。`netlib` 遇到人机验证会自动停用该源，这是有意设计的，不要绕过。

**补摘要的数据源**在 `ps/enrich.py`（`meta` 子命令），可以用同样的方式接入。

## E5. 修改图形界面

- 前端是纯 HTML/JS/CSS，在 `web/` 里（`app.js` 是主要逻辑），**不需要任何构建工具**，改完刷新浏览器就能看到效果。
- 后端是 `ps/server.py`。新增接口：写一个 `Handler` 方法，然后在文件末尾的 `ROUTES` 里登记，例如 `(r"/api/myfeature", Handler.myfeature)`。
- 安全约定：服务只监听 127.0.0.1；所有写操作（POST/PATCH/PUT/DELETE）必须带 `X-PS: 1` 请求头（前端的 `api()` 函数已自动加上），用来防止网页跨站提交。新增接口请保持这个约定。
- 公式渲染（可选）：下载 KaTeX，把 `katex.min.js`、`katex.min.css` 和 `fonts/` 放到 `web/vendor/katex/`，刷新即自动启用。

## E6. 接入新的 AI 工具

`AGENTS.md` 已经是通用格式。如果某个 AI 工具读的是其他文件名：

- 最省事的办法：在它的配置里把上下文文件指向 `AGENTS.md`。

- 如果它支持自定义斜杠命令，可以仿照 `.claude/commands/` 做一层薄壳，每个命令只写“打开 `docs/workflows/<名字>.md` 并照做”。

**不要**把规则复制到多个文件里分别维护，以后一改就会不一致。
