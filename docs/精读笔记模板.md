# 精读笔记模板（论文库 AI 精读的标准输出）

> 适用：queue 工作流（`/queue`）的精读任务，以及在本工作站里直接要求“精读/读一下库里第 N 篇”。
> 本模板**优先于**你所用 AI 工具自带的论文阅读模板或技能（例如“零遗漏图表公式”“下载图片”这类规则在这里不适用）。
> 想改笔记格式：直接编辑本文件即可，AI 下次精读就会按新格式写。

## 写作规则

1. **读者要的是论文的创新思路**：背景 → 相关问题 → Idea → 模型框架/机制 → Contributions。这条主线是全文重点，各节都要围绕它写，并在“创新思路主线”一节里串起来、标出对应章节。
2. **不要**写“关键公式”“关键图表”两节；**不要**提取、保存或嵌入论文图片（需要看图时用户自己看 PDF）。可以为理解架构查看框架图，但不保存。
3. **锐评不写“关键缺口与适用边界”**，不替论文挑错（排版、编号、图注错误等不写）。证据强弱（是否显著、提升是否在误差内）可以在判决和“最强证据”里一句话交代。
4. **方法详解写模块的宏观作用**（这个模块为什么存在、解决哪个问题），实现细节一两句带过。模块标题里写出它对应的问题。
5. **公式一律纯文本**：用 Unicode 符号（α β γ σ τ Σ √ · × ‖ ⊙ ∈ ⁻¹ ᵀ ²），下标写成 `x_v`、`f_s`，不用 `$…$`、`$$…$$` 或 LaTeX 命令；不要用 `*` 表示乘号（会被渲染成斜体）。需要时放进 ```text 代码块。
6. 正文首次出现的技术术语用 `[[概念]]` 链接；需要新建概念笔记时放在 `library/ai_notes/_概念/<概念名>.md`（一两段解释 + 出现过的论文），**概念笔记中的公式同样用纯文本**。
7. 笔记必须含论文 DOI 或 arXiv 链接（用于自动关联）。所有数字和结论必须来自原文；没读到的内容写“未读到/未核实”。
8. 保存位置：`library/ai_notes/<大组>/<小组>/<方法名>.md`（按论文在文献库中的分组）；无方法名时用论文简称并在开头说明。
