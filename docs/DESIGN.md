# 论文搜索工作站 · 总体设计

## 1. 要达到的效果（一句话）

**提一个研究问题 → 按你认可的出处与年份优先级，查全历史论文 + dblp 还没收录的最新论文 →
挑出的论文进入你的个人文献库 → 库里边用边补全（摘要、PDF、AI 分析、笔记、关联）→ 随时导出引用。**

```
            ┌──────────────── 交互层 ────────────────┐
            │  AI 助手（Claude Code / Codex …）         │  检索、筛选、精读、核验
            │  图形化论文库（浏览器，127.0.0.1:8765）     │  浏览、筛选、阅读、笔记、关联
            └───────────────┬────────────────────────┘
                            │ 读写同一个库
            ┌───────────────▼────────────────────────┐
            │  个人文献库 library/library.sqlite        │  ← 越用越全
            │  论文 · 补全状态 · PDF · 笔记 · 分组 · 关联 │
            └───────────────┬────────────────────────┘
                            │ 检索命中 / 手动加入
   ┌────────────────────────▼──────────────────────────────────┐
   │ 目录层（知道“有哪些论文”）                                    │
   │  本地 dblp（数百万篇，离线、秒级）  +  在线源补 dblp 缺口         │
   │  OpenAlex · Crossref · OpenReview · arXiv · Springer            │
   └───────────────────────────────────────────────────────────┘
```

关键区分：**目录 ≠ 文献库**。
- 目录层：全世界的论文，只有“基本信息”（标题/作者/出处/年份/DOI），由 dblp 数据包提供。
- 文献库：只放你检索命中、挑选过、关心的论文（几百到几千篇），**这些才需要“详细信息”**。

## 2. 模块

| 模块 | 文件 | 作用 |
|---|---|---|
| 本地 dblp | `ps/dblp_build.py` → `data/dblp.sqlite` | 从 dblp XML 数据包构建，FTS 全文检索（按标题，词干化） |
| dblp 查询 | `ps/dblp_query.py` | 检索（层级/年份优先排序、arXiv 版去重）、出处查找、BibTeX |
| dblp 缺口 | `ps/fresh.py` | 优先出处中 dblp 尚未收录的新论文（期刊在线优先、新会议、OpenReview 录用、arXiv 录用声明） |
| 检索编排 | `ps/search.py` | gather（多组检索词 × 多层级 × 年份配额 → 候选池）→ finalize（入库、报告、BibTeX） |
| 文献库 | `ps/library.py` | 入库/合并、两层分组、关联、PDF、笔记、AI 任务队列、BibTeX |
| 补全 | `ps/enrich.py` `ps/pdfabstract.py` | L1 元数据（OpenAlex/Springer/arXiv）、L2 开放获取 PDF、从 PDF 提取摘要 |
| 精读准备 | `ps/pdfread.py` | PDF 全文/页面渲染到临时目录 |
| 核验 | `ps/verify.py` | 参考文献逐条核对，输出规范 BibTeX |
| 网络层 | `ps/netlib.py` | 读取 `.env`、统一限速、额度账本、429/人机验证处理 |
| 中间数据 | `ps/scratch.py` | 临时目录、候选池、下载残片的统一清理 |
| 图形界面 | `ps/server.py` + `web/` | 只监听 127.0.0.1 的小型 HTTP 服务 + 纯前端页面（无构建步骤） |
| AI 规则 | `AGENTS.md`（`CLAUDE.md` 引用它）、`docs/workflows/*.md` | 与具体 AI 工具无关的规则和工作流 |
| 配置 | `config/venues.yaml` `config/api_limits.yaml` | 优先出处与年份优先级；API 限额 |

## 3. 补全等级

| 等级 | 内容 | 何时获得 | 成本 |
|---|---|---|---|
| L0 目录 | 标题、作者、出处、年份、DOI、层级 | 进库即有（来自 dblp/检索结果） | 0 |
| L1 摘要 | 摘要、引用数、开放获取链接、arXiv 版 | 进库后补（按 DOI 查 OpenAlex **免费**；Springer 补缺；或从本地 PDF 提取） | ≈0 |
| L2 全文 | 本地 PDF | 开放获取的自动下载（arXiv/Unpaywall）；付费的由用户自己合法下载后关联 | 0 |
| L3 研读 | AI 精读分析、你的笔记、与其他论文的关联 | 加入 AI 精读队列，或自己写 | AI 用量 |

## 4. 关键技术决策

| 问题 | 方案 |
|---|---|
| dblp 网站会拦截自动访问 | 只用离线数据包；任何脚本都不在线访问 dblp |
| 纯 HTML 文件不能写数据库 | 本机运行一个极小的 Python 服务（只监听 127.0.0.1），写请求需带 `X-PS` 头，防跨站提交 |
| 界面能不能直接调用 AI？ | 不直接调用。界面里点“精读”→ 写入任务队列；在 AI 助手里说“处理队列”即执行。补摘要、下 PDF 这类不需要 AI 的，服务直接执行 |
| 支持多种 AI 工具 | 规则集中在 `AGENTS.md`，流程写在 `docs/workflows/`；各 AI 工具只需一个很薄的入口（如 `.claude/commands/`） |
| AI 与界面如何协作 | 两者读写同一个 `library.sqlite`：AI 检索结果马上出现在界面里；你在界面上的星标、笔记 AI 也能看到 |
| 重复论文（arXiv 版 vs 正式版） | 按 DOI/标题合并为一篇，保留各版本链接 |
| dblp 每月更新 | 文献库只引用 dblp 键，重建 dblp 不影响文献库 |
| API 额度 | `api_limits.yaml` 设定上限，`netlib` 统一限速、记账；429 只重试一次；遇人机验证立即停用该源 |
| PDF 版权 | 只自动下载开放获取版本；付费论文由用户自己下载后挂入 |
| 中间数据 | 统一放 `data/tmp/<任务>/`，任务结束即清理；候选池入库后删除 |
| 备份 | 文献库 = `library/` 整个文件夹，复制即备份 |

## 5. 笔记

- **我的笔记** = 纯文本（`library/notes/<id>.txt`，界面内自动保存）。
- **AI 分析** = Markdown（`library/ai_notes/`，界面内渲染；按 arXiv/DOI/标题自动关联论文），格式由 `docs/精读笔记模板.md` 决定。
- 公式默认以原文显示；把 KaTeX 的 `katex.min.js` / `katex.min.css` / `fonts/` 放到 `web/vendor/katex/` 后自动启用渲染。
